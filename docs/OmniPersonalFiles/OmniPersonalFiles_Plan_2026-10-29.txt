6. THE GUIDE (AI companion inside the app)
Idea: a helper that travels with the user, like a fairy / navigator (Navi, Fi) and a party member
that has its own abilities (Donald and Goofy in Kingdom Hearts): it can DO things while the
user works, not only talk.
Original character: use these only as inspiration. Make its name, look and voice your own
(working name: OmniGuide), so there is no copyright or trademark trouble.

What it should do (ordered by how cheap and safe each is)
  1. Know where you are: reads the current selection, camera place, open panels.   [free, local]
  2. Explain: what is this node / tool / word, in plain language, with the shape legend. [free]
  3. Suggest the next step, as an Omni command the user can accept with one tap.      [free]
     The Omni language is already a safe action surface: commands have summaries, props,
     and destructive ones need the word "confirm". The guide proposes, the user approves.
  4. Do small jobs on request: arrange nodes, rename, remix, export a .omni.json, run a script. [free]
  5. Help with the Problem Reality (section 7): ask for criteria, point out missing evidence,
     compare solutions, state its assumptions.                                          [needs a language model]
  6. Natural-language chat for anything else.                                           [needs a language model = costs money]
Build order: 1-4 as a rule-based guide first (no cost, works offline). Add the language model
only for 5-6, behind a server that holds the key, with per-client caps (section 3).
Rules: it never acts without a visible proposal; every action is undoable or needs confirm; it
shows why it suggests something; it can be turned off or made quiet; it never invents facts about
the user's own reality.
Needs from the owner: personality (calm? playful?), the party-member abilities list, and the
look (a shape-based body fits "stupid simple").


7. PROBLEM REALITY (the core thesis, not built yet)
Nodes = facts, actors, constraints. Edges = cause / dependency. Criteria = weighted rules
people agree on. Solutions = nodes scored against the criteria, with the evidence and
assumptions shown. Anyone can change a weight and watch the ranking move.
Build ONE thin example end to end (a real, small problem) before building more tools.
