# OmniSense

Referenced across four other docs for a long time before it had a
real definition — always as a dependency, never as a specified
thing. It now has one, given directly while designing
OmniAddressCryptex (`architecture/OMNICRYPTEXLAB_DESIGN.md`):

**OmniSense controls symbols — specifically Unicode symbols — and
what those symbols grant access to: their meaning, and which
realities and experiences they resolve to.**

This came out of a real, separate research finding worth recording:
there is no global metric that works across physical, digital, and
logical scales — each has its own, incompatible unit. The fix isn't
a numeric metric at all; it's a **meta-metric** built from symbols
instead of numbers. That meta-metric *is* OmniSense.

## Where it was already referenced, before it had this definition

All four resolve cleanly under the real definition, retroactively —
none of them needed a different OmniSense than the one that actually
exists now:

- `COORDINATE_NODES_TIMELINE_DESIGN.md` — "communicating intent and
  experience, not just data" — exactly what a symbol/meaning system
  does, described before it had a name.
- `OMNI_NODE_IDENTIFICATION_DESIGN.md` — space gridification — a
  plausible application of symbol-based addressing to spatial
  structure.
- `OMNI_EXPRESSION_PRESENTER_DESIGN.md` — named as one of the two
  biggest roadmap items, alongside OmniChronos — consistent with it
  being a real, foundational, meta-metric-level system.
- `OMNICOMMUNICATION_SUITE_DESIGN.md` — OmniReceiver's symbol-based
  node identification is hard-blocked on OmniSense — this is now
  literal, not just thematically related: OmniReceiver needs the
  actual symbol-to-meaning resolution OmniSense *is*.

## Where it's load-bearing right now

- **OmniAddressCryptex** (`architecture/OMNICRYPTEXLAB_DESIGN.md`) —
  the addressing system's meta-metric is a direct OmniSense
  application, not a separate, parallel system.
- **Grabbing a Reality** (`architecture/HAND_TOGGLE_CONTROL_DESIGN.md`)
  — Tier 1's expand-vs-link decision still depends on OmniSense
  being able to resolve what a given reality's symbol/address
  actually means and where it should go.

## Status

Still no code, no data model for the symbol-to-meaning mapping itself.
But no longer an undefined dependency — this doc records the real
definition, not just the fact that other things need it.
